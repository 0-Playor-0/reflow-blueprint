Ideation

Find the gaps before a judge does

Paste the rubric, drop a link, or upload the PDF. An LLM call parses it into structured criteria against a strict schema. If the source has no explicit weights or fewer than three criteria, ReFlow falls back to a defaults library keyed by hackathon type — and shows the inference, editable inline, rather than hiding the guess. Scoring runs one LLM call per criterion, not one call for everything. The output that matters isn't the number: it's the gap list — missing features, scope that's unrealistic for the time left, weak-rubric-area gaps — each with a suggested fix.

Planning

Turn the idea into tasks people can actually finish

Generation runs in two passes: the idea and rubric become 4–7 top-level features, one flagged demo-critical, then each is expanded independently into 3–6 leaf subtasks classified against a fixed archetype taxonomy — not free text, and capped in depth on purpose, because a deeper tree is unmanageable at hackathon speed. Effort comes from a maintained reference table (archetype × size × assignee familiarity), not an LLM guessing hours. Skill signals come from language bytes, dependency manifests, and recency-decayed commit history mapped onto a fixed taxonomy with cited evidence — plus a self-declared checklist as the primary path, not a fallback, since most participants' GitHub history is thin. Assignment solves a global cost matrix (Hungarian algorithm) balancing fit against capacity, with a stated buffer per person.

Review

Rehearse the questions judges will actually ask

Retrieval runs over your team's actual repo, not a generic FAQ. Chunking is syntax-aware — one chunk per function, class, or component, not fixed character windows, because naive chunking on code destroys retrieval quality. Question targets are chosen deliberately: highest-churn files, files touching auth or secrets or data, the largest or most-nested functions, TODO/FIXME comments, dependencies added right before submission. The standout category checks README and pitch claims against what the code actually does. Every question cites the exact file and line range and renders the cited code alongside it, so a question that isn't traceable to real code is visibly wrong instead of plausibly hallucinated.

Analytics

See who did what — and where that log goes blurry

Commit attribution runs multiple methods in priority order: branch name match, task reference in the commit message, touched-file overlap, LLM classification as a last resort. Every attribution records which method produced it and at what confidence, so a low-confidence guess is shown differently from a branch-name match rather than presented with equal certainty. Metrics deliberately exclude lines of code, since that rewards lockfiles and copy-paste, in favor of commits by day and feature, features completed versus assigned, breadth of areas touched, and blockers raised and resolved. This is an activity log that requires human interpretation — not a fair, evidence-based record of who built what.

activity log needs human interpretation
  • auth.py refactor → Jaebranch match · high confidence
  • styles.css cleanup → unclearLLM guess · low confidence

Pairing, debugging someone else's code, design work, and demo prep are all invisible to git. Read this as a conversation starter for the team, not a scoreboard.

Infrastructure, not a stage

Two separate GitHub grants

A light OAuth grant at signup covers public language, dependency, and commit signals for skill profiling. A narrow per-repo GitHub App install happens only when the team links their repo for Review. These are deliberately not the same permission.

Jobs run in the background

Rubric parsing, GitHub crawling, repo indexing, question generation, and PDF export are queued through Redis and run as background jobs. Postgres holds the actual state; the queue is transport only. The client subscribes to a per-team stream for progress.

Worker capacity is prioritized

Deadline-proximate Review and Analytics jobs run ahead of routine recomputation. Lane sizes are set against the LLM provider's actual rate limit, not a guessed worker count.

The gap list is the pitch. The activity log is a conversation, not a verdict.

ReFlow doesn't stop at a plan. The repository keeps talking back — through Review, through Analytics — for as long as the team is building.
